# AutoPlay 1.5.4 界面收口：全部界面按两张主页面的规矩走一遍；名字统一以 AutoPlay 开头

日期：2026-11-14。承接 1.5.0（`docs/UI-1.5.0.md`，盒子网页与「AutoPlay 设置」同构）和 1.5.1（标题栏位置以盒子网页为准）。

车主的要求（2026-11-13）：把所有界面、各种情况下可能出现的样子完整看一遍，找出和「AutoPlay 设置」「AutoPlay 盒子」两张主页面的设计思路不一致的地方，比如小字。审查在电脑的 Chromium 里按特斯拉的窗口（773×601）、日间/夜间、手机尺寸逐个状态截图（盒子网页 30 多个状态、投屏页的等待/连接/出错/浏览器检测等），对照的规矩是这两张页面已经在用的：

- 行就是图标、名称、灰色的值和尖角，和 iOS「设置」一样；
- 不放常驻的说明文字；分组下面的一行字只在有事发生时出现；
- 一件事一屏（添加 iPhone、确认、恢复出厂设置）时：标题栏写这件事，右上角「取消」，正文里只有做这件事的那个按钮；
- 日间、夜间两套颜色，盒子网页和面板逐项相同。

审查找到 14 处，车主要求全部处理，第 12 处（命名）由车主提出统一方案。

## 一、14 处和处理

| # | 哪里 | 问题 | 处理 |
|---|---|---|---|
| 1 | 盒子网页，配对完成后 | 「配对完成，iPhone 正在连上 Wi-Fi 并打开 CarPlay」（现在说「AutoPlay 热点」）占满整页，没有分类、没有「返回」，而且一直留到下一次配对或盒子重启——iPhone 没来的话车主就困在这一屏 | 回到正常页面，这句话作为 iPhone 分组下的一行；页面每 3 秒刷新直到 iPhone 连上，最多 3 分钟（配对状态里记下完成时间 `at`；没有 `at` 的旧状态不再显示） |
| 2 | 投屏页，浏览器检测 | 旧样式（细线表格、技术详情折叠），通过后还写着"首次出声前需要轻点"——1.3.0 起页面不出声 | 改成面板的样子：标题栏（检测完成后右上角「完成」），每项检测一行、结果作为值（通过 / 缺少 / 受限），只有没通过的一项下面写原因；浏览器自己的上报（UA）只在有问题时出现。尺寸用面板的根字号算，即使播放器脚本没加载也一样大 |

## 二、名字（第 12 处）

车主的提议：相关命名都以 AutoPlay 开头，加上热点、设置等。采用，规则是**一个东西一个名字，名字就是它出现在屏幕上的标题**：

| 东西 | 名字 | 出现的地方 |
|---|---|---|
| 盒子发出的 Wi-Fi（交给 iPhone、车机也连它） | **AutoPlay 热点** | 盒子网页「网络」的分组标题、连接链第一个圆点下面、等待画面的提示、LuCI 的说明、安装说明 |
| 投屏页的设置面板 | **AutoPlay 设置** | 面板标题；CarPlay 主屏上的图标（原来叫「盒子设置」） |
| 盒子网页（`:18080`） | **AutoPlay 盒子** | 页面标题；面板「连接」里打开它的那一行（原来叫「打开盒子网页」）；LuCI 和安装说明里提到它的地方 |

不改的：「CarPlay 画面」（投屏页本身，按钮和 LuCI 里都这么叫，说的是 CarPlay 而不是 AutoPlay）；句子里的「盒子」（「检查盒子电源」「盒子以出厂状态重新启动」）——说的是那台设备，不是某个页面。热点的真实名字（SSID，例如 AutoPlay-5G）仍按 OpenWrt 里设的显示，「AutoPlay 热点」是它的角色名。

CarPlay 图标的名字由 iPhone 画在图标下面，较长时会被截成「AutoPlay…」。台架上看不到这一点，要上车确认（§四）；如果截了，退路是只写「AutoPlay」。

## 二甲、第二轮：一件事一屏的小字和按钮，对照苹果的 HIG

车主看过第一轮后指出（2026-11-14）：恢复出厂设置等页面还有小字；添加、删除 iPhone 页里像「删除」这样的按钮，是否不符合苹果官方的设计要求。对照 Apple Human Interface Guidelines 的 Buttons、Alerts、Action sheets 三页，确实有几处不符：

| HIG 的规定 | 原来 | 现在 |
|---|---|---|
| 破坏性操作不要做成醒目的主按钮（"Don’t assign the primary role to a button that performs a destructive action"）；破坏性按钮用系统红色的文字 | 「删除」「恢复出厂设置」是整行宽、红底白字的大按钮 | 列表里的一行红字（「删除此 iPhone」「恢复出厂设置」），和主页面上「删除此 iPhone…」同一种行 |
| 按钮标题用动词，说清按下去的结果；不用 Yes / No 式的标题；取消就叫「取消」 | 配对屏两个大按钮「不一致」「一致」，下面一行解释两个按钮 | 一行「配对」（iPhone 自己的配对请求也用这个词），「取消」在标题栏；手机名字作为卡片第一行，配对码在它下面 |
| 操作表 / 提示的说明文字只在必要时出现，标题加上下文通常够了 | 删除屏的「删除后要再用，需要重新添加。」、手机名下的「蓝牙 …00:02」；升级屏的「会先备份配对和设置；新版本起不来会自动退回。」 | 去掉。蓝牙地址只在两部手机同名时出现（和主页面一样） |
| 一个视图里醒目的按钮最多一两个；用样式而不是大小区分 | 盒子网页只有这几屏用整行宽的填色按钮，其余操作都是列表里的行 | 全部是行：蓝字是操作，红字是破坏性操作；填色按钮和它们的样式删除了 |

恢复出厂设置：三行只留名字（原来每行下面一行明细），去掉两个分组的脚注和「确认」标题；要删认证文件时输入什么，写在输入框的占位文字里（「输入「删除认证文件」」）。两次输入确认照旧——认证文件删了无法恢复，这一步不放宽。

添加 iPhone：去掉「怎么做」三步和「正在连接」那一行下面的小字。

标题栏右上角的「取消」「返回」「完成」是带底色的圆角按钮，接近 iOS 26 起标题栏按钮带底的样子，这一轮没有改。

## 二乙、第三轮：讲怎么做、要多久的小字一律不要

车主的思路（2026-11-14）：添加 iPhone 页的「在 iPhone 上打开……」、升级页的「约 2–5 分钟……」这类表述都是多余的。按这个规矩再过一遍，规则定为：**分组下面的一行字只用来报告结果或说明现在为什么做不了；讲怎么做、要多久的一律不写**（做法写在安装说明里）。

| 去掉的 | 在哪儿 |
|---|---|
| 「在 iPhone 上打开「设置 → 蓝牙」并停在那一页。本页在车机或另一台设备上打开：地址」 | 添加 iPhone |
| 「和「X」上的数字相同时，两边都点「配对」。」 | 配对码（手机名字改为卡片第一行，配对码在它下面——原来名字只在这句里） |
| 「约 2–5 分钟，期间 CarPlay 断开。」 | 升级确认、升级进行中；点「立即升级」后的结果也只说「已开始升级」。正在用 CarPlay 时盒子本来就拒绝升级，这句提醒保护不了什么 |
| 「已邀请，1 分钟内有效。请保持 iPhone 的蓝牙打开。」 | 接入 CarPlay 之后，改为「已邀请。」 |
| 「通常约 5 秒」 | 投屏页「正在调整画面」下面，和改设置后画面上的提示 |

留下的（都是结果或现在为什么做不了）：「配对完成，iPhone 正在连上 AutoPlay 热点并打开 CarPlay。」「蓝牙就绪后才能添加或接入 iPhone。」「这一版改了系统，需要按发布说明手动升级。」、操作被拒绝的原因、升级进行中那一行的进度；投屏页连不上盒子、拿不到访问许可、浏览器不支持时的那一句。LuCI 后台是 OpenWrt 的界面，不在这一轮里。

## 三、怎么复现

```sh
cd box && python3 -m unittest discover -s tests/onecloud     # 盒子侧，含 1.5.4 新增的 4 个
cd receiver/web && npm run build:offline && npm test         # 投屏页
python3 ../../box/tools/render_settings_states.py out/box-states
BOX_STATES=out/box-states node scripts/ui-shots.mjs out/ui-shots twins   # 两张页面 7 种窗口 × 有/无标题，全部 same
```

## 四、要在车上确认的

- CarPlay 主屏上「AutoPlay 设置」图标的名字是否完整显示。
- 浏览器检测的新样子在特斯拉浏览器里的字号（它在播放器脚本之前画，用自己的几条样式）。
- 配对完成后，iPhone 连上时 iPhone 分组下面那行字是否自己消失（每 3 秒刷新，最多 3 分钟）。
