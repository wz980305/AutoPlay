# 安全

## 1. 威胁模型（现状）

**今天的安全边界就是热点密码。** 连上 F50 的 WPA2 热点，等于拿到全部控制权（《加固路线图》WP7）：

- 看 CarPlay 画面、操作 iPhone（WSS 只校验一个"仅本页"令牌，令牌从 `receiver-access.json` 取，永不轮换）。
- 设置页 `http://100.96.0.1:18080/`：明文、无认证、不校验 Host；能删配对、添加 iPhone、触发升级、改 DuckDNS 令牌。
- LuCI `http://100.96.0.1/`：有密码，但较旧的 mu300 镜像里 HTTPS 私钥所有设备共用一把（PA#3）。
- 有数据线就有 root：较新的 mu300 镜像默认在 USB 上开 adb，无密钥（PA#15）；接在车机数据口上时 F50 还暴露 NCM 网卡和 ACM 串口。
- SD 卡可以拔走：上面有身份文件、配对信息、本地 CA 私钥（有效期 10 年、无名称约束）、DuckDNS 令牌、TLS 私钥。

在这个边界下，谁在车里、谁知道 Wi-Fi 密码：车主、乘客、以及任何曾经上过这辆车并存过密码的人。盒子不暴露到外网（SIM 卡是 CGNAT，LuCI 和设置页只监听局域网，fw4 的 WAN 入站默认拒绝）；真正的远程面只有 DuckDNS 的 DNS 记录（指向 100.96.0.1，没有可路由的信息）。

## 2. 身份材料

- CarPlay 要求配件通过 Apple 认证。本仓库、软件包、文档、测试**不包含**任何配件身份、证书或私钥；接收端在 `identity/offline-mfi/` 没有用户自行放置的 `identity.pk8` + `certificate.p7b` 时拒绝启动，不会自动下载。`.gitignore` 排除 `identity/`。
- 公开流传的那份身份是全网共用的：Apple 一次撤销让所有安装同时失效；分发它有法律风险；任何人都能冒充这个配件，所以它**不提供任何身份保证**（技术路径 §3.8）。
- 签名做成接口（PlayPort 的 `MfiAuthenticator`，在 `MfiIdentity.load` 里选实现）：本地文件、远程签名服务、硬件芯片三种实现可替换，身份被撤销时换实现，不改协议。
- 合规路径是真正的 MFi 芯片，但 F50 没有 USB 主机也没有 I²C 引出，只能由另一台装了芯片的设备做远程签名（xcertplay、PlayPort 都支持）。

## 3. `tools/f50/harden.sh` 改变了什么

| 改动 | 关掉的风险 | 来源 |
|---|---|---|
| 重新生成 uhttpd 的 TLS 密钥（一次） | 镜像共用的 LuCI 私钥：局域网里能冒充 LuCI | PA#3、WP7 |
| `mu300-usb adb off` | 插线即 root | PA#15、WP7 |
| `dl_reboot=0`、启动尝试 6 次 / 锁定 | 不是安全项，但减少"被重启到原厂安卓"这种可用性失效 | PA#1、PA#5 |
| `/var/run/autoplay` 独立 tmpfs 64MB、核心转储到 `/dev/null`、`oom_score_adj` | 日志把内存吃光、崩溃时把内存倒进 tmpfs、OOM 先杀底层 | H9 |
| `tune2fs -e remount-ro`（`--fs`） | 在损坏的文件系统上继续写 | H7 |

它**没有**改热点密码、没有给设置页加认证、没有动防火墙。

## 4. 仍然存在、计划中的

按 WP7 和 dashplay-tesla 分析 §五的教训排序：

1. **破坏性操作要 PIN**：配对、删除配对、升级、重置，由车主在设置页输入 PIN；同一时间只允许一个控制端；可选的车机白名单（按 MAC/IP）。
2. **设置页加 Host 白名单和 `X-Frame-Options: DENY`**；删掉无认证的状态接口（dashplay-tesla 在 8443 上把唯一凭据写进热点可读的静态文件，是反面教材）。
3. **每设备令牌**代替一个全局令牌：配对时签发，可撤销，可轮换。
4. **换一个又长又新的 WPA2 密码**（安装脚本生成随机密码并只显示一次）；SC2355 只支持 WPA2-PSK，没有 WPA3 可选。
5. **本地 CA**：加 `nameConstraints`、缩短有效期、重置时轮换；特斯拉装不了 CA，所以 D7 建议干脆去掉本地 CA，只留 Let's Encrypt 和 JVM 自签名兜底。
6. **私有 BlueZ 冻结**在安装时的版本，收不到安全更新；升级时要从软件源重建。apk 也没有签名（WP9）。
7. **恢复出厂设置**：卸载后身份文件、CA 私钥、配对信息都还在卡上；要在 LuCI 和设置页加"重置"并安全擦除。
8. **iAP2 调试日志默认关**：上游 10.25 仍默认记录，里面有来电号码和联系人（dashplay-tesla 分析 §三第 9 项）。
9. **远程维护通道**（如果做服务器端续期）：强制密钥登录或改用 WireGuard，不走"反向 SSH 直通 root"（dashplay-tesla 分析 §五第 2 条）。
10. **车机数据口**：用纯供电线或车充口，不让 F50 在车机上枚举成网卡和串口。
11. **SSH**：F50 上 DashPlay 的安装脚本每次生成随机 root 密码并改用密钥；设置页里"root/1234"的提示是错的（只对 N1/玩客云成立），要改文案（S3）。

## 5. 隐私

盒子上的日志里有 Wi-Fi MAC、蓝牙地址、手机名、iOS 版本、SSID；诊断导出时应截短 MAC；DNS 查询日志（特斯拉模式用来看联网检测）默认按需开启。探测页（`tools/probe/`）不上传任何东西，"POST 到盒子"只在点击时发到用户填写的地址。测量服务（`tools/f50/measure.sh`）只记录系统指标和到车机 IP 的 TCP 统计，不记录流量内容。
