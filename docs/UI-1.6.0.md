# AutoPlay 1.6.0 界面收口：全部界面按两张主页面的规矩走一遍；名字统一以 AutoPlay 开头

日期：2026-11-14。承接 1.5.0（`docs/UI-1.5.0.md`，盒子网页与「AutoPlay 设置」同构）和 1.5.1（标题栏位置以盒子网页为准）。

车主的要求（2026-11-13）：把所有界面、各种情况下可能出现的样子完整看一遍，找出和「AutoPlay 设置」「AutoPlay 盒子」两张主页面的设计思路不一致的地方，比如小字。审查在电脑的 Chromium 里按特斯拉的窗口（773×601）、日间/夜间、手机尺寸逐个状态截图（盒子网页 30 多个状态、投屏页的等待/连接/出错/浏览器检测等），对照的规矩是这两张页面已经在用的：

- 行就是图标、名称、灰色的值和尖角，和 iOS「设置」一样；
- 不放常驻的说明文字；分组下面的一行字只在有事发生时出现；
- 一件事一屏（添加 iPhone、确认、恢复出厂设置）时：标题栏写这件事，右上角「取消」，正文里只有做这件事的那个按钮；
- 日间、夜间两套颜色，盒子网页和面板逐项相同。

审查找到 14 处，车主要求全部处理，第 12 处（命名）由车主提出统一方案。

## 一、14 处和处理

| # | 哪里 | 问题 | 处理 |
|---|---|---|---|

## 二、名字（第 12 处）

车主的提议：相关命名都以 AutoPlay 开头，加上热点、设置等。采用，规则是**一个东西一个名字，名字就是它出现在屏幕上的标题**：

| 东西 | 名字 | 出现的地方 |
|---|---|---|
| 盒子发出的 Wi-Fi（交给 iPhone、车机也连它） | **AutoPlay 热点** | 盒子网页「网络」的分组标题、连接链第一个圆点下面、等待画面的提示、LuCI 的说明、安装说明 |
| 投屏页的设置面板 | **AutoPlay 设置** | 面板标题；CarPlay 主屏上的图标（原来叫「盒子设置」） |
| 盒子网页（`:18080`） | **AutoPlay 盒子** | 页面标题；面板「连接」里打开它的那一行（原来叫「打开盒子网页」）；LuCI 和安装说明里提到它的地方 |

不改的：「CarPlay 画面」（投屏页本身，按钮和 LuCI 里都这么叫，说的是 CarPlay 而不是 AutoPlay）；句子里的「盒子」（「检查盒子电源」「盒子以出厂状态重新启动」）——说的是那台设备，不是某个页面。热点的真实名字（SSID，例如 AutoPlay-5G）仍按 OpenWrt 里设的显示，「AutoPlay 热点」是它的角色名。

CarPlay 图标的名字由 iPhone 画在图标下面，较长时会被截成「AutoPlay…」。台架上看不到这一点，要上车确认（§四）；如果截了，退路是只写「AutoPlay」。

## 二甲、第二轮：一件事一屏的小字和按钮，对照苹果的 HIG

车主看过第一轮后指出（2026-11-14）：恢复出厂设置等页面还有小字；添加、删除 iPhone 页里像「删除」这样的按钮，是否不符合苹果官方的设计要求。对照 Apple Human Interface Guidelines 的 Buttons、Alerts、Action sheets 三页，确实有几处不符：

| HIG 的规定 | 原来 | 现在 |
|---|---|---|
| 破坏性操作不要做成醒目的主按钮（"Don’t assign the primary role to a button that performs a destructive action"）；破坏性按钮用系统红色的文字 | 「删除」「恢复出厂设置」是整行宽、红底白字的大按钮 | 列表里的一行红字（「删除此 iPhone」「恢复出厂设置」），和主页面上「删除此 iPhone…」同一种行 |
| 按钮标题用动词，说清按下去的结果；不用 Yes / No 式的标题；取消就叫「取消」 | 配对屏两个大按钮「不一致」「一致」，下面一行解释两个按钮 | 一行「配对」（iPhone 自己的配对请求也用这个词），「取消」在标题栏；手机名字作为卡片第一行，配对码在它下面 |
| 操作表 / 提示的说明文字只在必要时出现，标题加上下文通常够了 | 删除屏的「删除后要再用，需要重新添加。」、手机名下的「蓝牙 …00:02」；升级屏的「会先备份配对和设置；新版本起不来会自动退回。」 | 去掉。蓝牙地址只在两部手机同名时出现（和主页面一样） |
| 一个视图里醒目的按钮最多一两个；用样式而不是大小区分 | 盒子网页只有这几屏用整行宽的填色按钮，其余操作都是列表里的行 | 全部是行：蓝字是操作，红字是破坏性操作；填色按钮和它们的样式删除了 |

恢复出厂设置：三行只留名字（原来每行下面一行明细），去掉两个分组的脚注和「确认」标题；要删认证文件时输入什么，写在输入框的占位文字里（「输入「删除认证文件」」）。两次输入确认照旧——认证文件删了无法恢复，这一步不放宽。

添加 iPhone：去掉「怎么做」三步和「正在连接」那一行下面的小字。

标题栏右上角的「取消」「返回」「完成」是带底色的圆角按钮，接近 iOS 26 起标题栏按钮带底的样子，这一轮没有改。

## 二乙、第三轮：讲怎么做、要多久的小字一律不要

车主的思路（2026-11-14）：添加 iPhone 页的「在 iPhone 上打开……」、升级页的「约 2–5 分钟……」这类表述都是多余的。按这个规矩再过一遍，规则定为：**分组下面的一行字只用来报告结果或说明现在为什么做不了；讲怎么做、要多久的一律不写**（做法写在安装说明里）。

| 去掉的 | 在哪儿 |
|---|---|
| 「在 iPhone 上打开「设置 → 蓝牙」并停在那一页。本页在车机或另一台设备上打开：地址」 | 添加 iPhone |
| 「和「X」上的数字相同时，两边都点「配对」。」 | 配对码（手机名字改为卡片第一行，配对码在它下面——原来名字只在这句里） |
| 「约 2–5 分钟，期间 CarPlay 断开。」 | 升级确认、升级进行中；点「立即升级」后的结果也只说「已开始升级」。正在用 CarPlay 时盒子本来就拒绝升级，这句提醒保护不了什么 |
| 「已邀请，1 分钟内有效。请保持 iPhone 的蓝牙打开。」 | 接入 CarPlay 之后，改为「已邀请。」 |
| 「通常约 5 秒」 | 投屏页「正在调整画面」下面，和改设置后画面上的提示 |

留下的（都是结果或现在为什么做不了）：「配对完成，iPhone 正在连上 AutoPlay 热点并打开 CarPlay。」「蓝牙就绪后才能添加或接入 iPhone。」「这一版改了系统，需要按发布说明手动升级。」、操作被拒绝的原因、升级进行中那一行的进度；投屏页连不上盒子、拿不到访问许可、浏览器不支持时的那一句。LuCI 后台是 OpenWrt 的界面，不在这一轮里。

## 二丙、车主的核心要义：小字可以有，但要简洁、凝练、言之有物，以苹果系统的做法为参照

车主（2026-11-14）把前两轮归结为一句：小字可以有，但一定是简洁的、凝练的、言之有物的；这一块以苹果官方系统里的逻辑和思路为参照。iOS 自己的做法：

- **顺利进行的流程下面不写怎么做。** 「设置 › 蓝牙」找设备时只有列表和转圈，没有步骤说明；所以添加 iPhone、配对码、升级确认不写说明（§二乙）。要停在蓝牙页这句，只在配对真的没有被确认时出现：「iPhone 没有确认配对：让它停在「设置 → 蓝牙」，再点一次它的名字。」
- **出错时，一句说清发生了什么，再给一个能做的动作。** 不叠加第二、第三个办法，不解释原理。
- **进行中只说在做什么。**「正在安装」，不再附「CarPlay 会断开约 1 分钟」。
- **确认框只有标题和按钮，必要时一句话**（Action sheets：「Provide a message only if necessary」）。

按这几条把两张页面上还长的句子收短：

| 原来 | 现在 |
|---|---|
| 蓝牙没有启动：原因。可以重启盒子；仍不行请下载诊断记录。 | 蓝牙没有启动：原因。请重启盒子。 |
| 有一部 iPhone 忘记了这台盒子（连续两次拒绝连接），请删除此 iPhone 后重新添加。 | 有一部 iPhone 忘记了这台盒子，请删除它后重新添加。 |
| 证书已于……过期，车机浏览器会提示不安全。盒子没网，无法续签：插上能上网的 SIM 卡开机一次。 | 证书已于……过期，车机会提示不安全。盒子没网无法续签，请插上能上网的 SIM 卡。 |
| 还缺 CarPlay 认证文件：把「AI 安装说明」、盒子地址……和安装时记下的登录方式交给你的 AI 助手。放好后自动开始工作；添加 iPhone 可以先做。 | 还缺 CarPlay 认证文件，按「AI 安装说明」放好后自动开始工作。 |
| 盒子过热（…），系统正在降低它的速度，CarPlay 可能卡顿。请把它移到晒不到的地方或靠近出风口。 | 盒子过热（…），正在降速，CarPlay 可能卡顿。请移到晒不到的地方。 |
| 已重置（N 项）。盒子约 1 分钟后重新启动，之后请重新添加 iPhone。 | 已重置。盒子正在重新启动，之后重新添加 iPhone。 |
| 配对请求已取消或超时。请重新发起，并及时在手机和盒子页面确认相同的数字。 | 配对已取消或超时，请重试。 |
| 当前有人使用 CarPlay，不会自动抢占；请对方先断开 Wi-Fi 或 CarPlay。 | 有人正在用 CarPlay，请对方先断开。 |
| AutoPlay 热点的信道……特斯拉看不到（它只认 36–48 和 149–165）。请在 OpenWrt 后台…… | 特斯拉看不到 AutoPlay 热点的信道……，请在 OpenWrt「网络 → 无线」改为 149（国家 CN）或 36。 |
| AutoPlay 热点还没准备好：……。请在 OpenWrt 后台「网络 → 无线」或「服务 → AutoPlay」检查；准备好后 AutoPlay 会自动继续。 | AutoPlay 热点还没准备好：……。请在 OpenWrt「网络 → 无线」检查。 |
| （投屏页）暂时无法连接盒子。请检查盒子电源与车机的 AutoPlay 热点连接。 | 连不上盒子，请检查盒子电源和 AutoPlay 热点。 |
| （投屏页）本页打开时没有从盒子取到访问许可。请检查……，然后刷新本页。 | 请检查盒子电源和 AutoPlay 热点，然后刷新本页。（标题已经说了没取到许可） |
| （投屏页）这台车机解不了 H.265。请把「显示 › 画质与兼容 › 视频编码」改为自动或 H.264。 | 这台车机解不了 H.265，请在「显示 › 画质与兼容」把视频编码改为自动。 |
| （投屏页）此浏览器缺少视频解码能力，请使用支持 WebCodecs 的浏览器。／当前页面不是安全上下文，请使用已受信任的 HTTPS 地址。 | 这台车机的浏览器不能解码视频，请更新车辆软件。／不是安全连接，请用盒子的 https:// 地址打开本页。（车里换不了浏览器，"安全上下文"是术语） |
| （投屏页）暂时无法连接视频网站，不能开启无边框模式。请检查车机网络，当前画面仍可使用。 | 车机连不上视频网站，暂时开不了无边框模式。 |
| （投屏页）车机解码跟不上 60 帧，已自动改为 30 帧（重新连接一次）。／已记下，下次连接 iPhone 时生效，不打断当前画面。／应用失败，请检查连接和分辨率范围。 | 车机解码跟不上 60 帧，已改为 30 帧。／下次连接 iPhone 时生效。／没有应用成功，请重试。 |
| （浏览器检测）特斯拉：在「控制 › 软件」更新车辆软件后再试；旧版本的浏览器不能解码视频。地址必须是盒子的 https:// 名称（证书受信任）。 | 请在「控制 › 软件」更新车辆软件后再试。（缺什么，上面那行已经写了） |

没有动的：LuCI 后台（OpenWrt 自己的界面）；「自己的网址」里填错格式时告诉你去哪儿复制的那几句（言之有物，也只在填错时出现）；局域网地址、Tailscale 这类很少出现、要照着做的技术提示。

## 二丁、第二次审查：对照苹果 HIG 的 17 章

车主要求在对苹果官方文档有了进一步了解的前提下，再完整审查一轮（2026-11-14）。读了 HIG 的 Toolbars、Sheets、Writing、Pop-up buttons、Progress indicators、Feedback、Accessibility、Color、Settings、Toggles、CarPlay、Lists and tables、Text fields、Typography、Loading、Going full screen、Alerts / Action sheets，两张页面每个状态按特斯拉窗口和手机、日间和夜间截图、量尺寸，找到 20 处。车主定：第 5 条（给看不出作用的设置加一行说明）先不做，其余 19 条做。

| # | HIG 的规定 | 原来 | 现在 |
|---|---|---|---|
| 1 | Sheets：单页表单的「取消」在标题栏左边 | 「取消」在右上 | 添加 iPhone、删除 iPhone、恢复出厂设置的「取消」在左上，标题居中 |
| 2 | Toolbars：用标准的返回按钮，用符号、不写「返回」二字 | 盒子网页右上角文字「返回」 | 左上角 ‹（从投屏页来时）；自己打开的浏览器在右上角仍是「CarPlay 画面」 |

## 二戊、弹出的提示，和文字的口吻

车主指着「这台车机解不了 H.265……」那个弹窗问：能不能也按这套思路优化，还有没有别的弹窗没改过；接着指出「（重新连接一次）」这样括号里的补充、「连接中断 · 正在重连 · 触控已暂停」这样用圆点串起来的句子有「AI 味儿」，「解不了」这样的说法太口语（2026-11-14）。车主喜欢「正在重连」那个胶囊提示的样子。

**弹出的提示分成三种，各按苹果的做法**（HIG Alerts、Feedback、Progress indicators）：

| 哪一种 | 原来 | 现在 |
|---|---|---|
| 要车主处理、处理之前不会有画面（车机不支持 H.265 而视频编码手选了 H.265；浏览器不支持视频解码；不是安全连接） | 左下角一张卡片，红色竖条，右上角文字「关闭」，解码器的英文收在「详细信息」里 | 苹果的提示框：屏幕中间，背后变暗，一个标题、一句话，下面并排两个按钮「好」和蓝底的「前往设置」（能用一个设置解决时）。解码器的原话不上屏，记进盒子的日志（viewer stats ev 17） |
| 页面自己已经处理好的事（已改用 H.264、已改为 30 帧、无法自动调整画面尺寸、无法开启无边框模式、解码出错正在重新获取） | 底部居中的胶囊，几行字 | 同一个胶囊样子，一行短句，几秒后自己消失；留在底部，不挡 CarPlay 顶部的导航提示 |
| 正在重新连接 | 画面中间的胶囊，「连接中断 · 正在重连 · 触控已暂停」 | 样子不变（车主喜欢），字改为「正在重新连接，触控已暂停」 |

盒子网页当时没有弹窗；它顶部的提示条前两轮已经改过（一句话说清情况，再给一个能做的事，关于热点的带 OpenWrt 链接）。下一轮（§二己）把它们改成标题加一行，做不成的操作改为提示框。

**括号里的补充和中间的圆点都去掉**：两张页面上显示的文字里，括号补充改成正常的句子或删掉（「已改为 30 帧（重新连接一次）」「不是安全连接（证书未受信任，或用了 http://）」「视频解码（H.264 / WebCodecs）」「5 GHz（国内信道 149）」「149（国家 CN）」「正在下载 1.6.0（38 MB）」等），「当前画面」的值和坐标系菜单里的说明改用逗号、冒号。`check-car` 核对：页面显示的文字里没有全角括号，也没有用「 · 」连接的短语。只给开发者看的调试信息不在此列。

**口吻改为 iOS 中文界面的写法**：「无法」代替「解不了」「连不上」「开不了」「打不开」，「未」「尚未」代替「没有」「还没」，「此」代替「这台」「这部」「这个」，要车主做的事前面加「请」。例如「此车机不支持 H.265 解码」「请将视频编码改为「自动」。」「无法连接盒子，请检查盒子电源和 AutoPlay 热点。」「蓝牙未启动」「证书尚未申请成功」「找不到此页面。」「CarPlay 正在使用中，请先断开再添加。」共六十来处，投屏页、浏览器检测、盒子网页、盒子的提示和升级结果都改了；只在命令行里出现的登记信息没动。

## 二己、提示框用到更多地方，常驻提示的写法

车主问：这套弹出的提示能不能用到更多场景，比如盒子网页上「蓝牙没有启动：蓝牙被另一个程序占用，请重启盒子。」；提示的字本身是不是也要再改，比如删去「蓝牙没有启动」。

**苹果怎么分**（HIG Alerts）：提示框只给「刚做的事没做成」和「现在必须处理」的情况；一直存在的状态（蓝牙没启动、证书快到期、没有 4G）不该每次打开页面都弹出来，而是在页面里用一个不打扰的提示。所以：

| 哪一种 | 原来 | 现在 |
|---|---|---|
| 常驻的状态（盒子网页顶部） | 一行长句，前面一个重复的前缀：「蓝牙未启动：蓝牙被另一个程序占用。请重启盒子。」 | 和提示框同一个结构：粗体一句说发生了什么，下面一行灰字说该做什么——「**蓝牙被另一个程序占用**／请重启盒子。」前缀去掉 |
| 刚点了、没做成（盒子网页） | 顶部一条红色提示；在「高级」等分类里它在看不见的上方 | 苹果的提示框，在页面中间、背景压暗：「**无法添加 iPhone**／CarPlay 正在使用中，请先断开。」「好」 |
| 刚点了、没做成（投屏页「应用」） | 分组下面一行「应用失败，请重试。」 | 同样的提示框：「**无法应用设置**／请检查与盒子的连接，再试一次。」页面自己调整画面失败时仍是底部的胶囊 |

**常驻提示的写法**：标题说发生了什么，第二行只在有能做的事时出现。蓝牙的每个原因直接作为标题（「蓝牙被另一个程序占用」「蓝牙芯片无响应」「蓝牙被系统关闭」……）；盒子已经在自己重启蓝牙的两种情况不再说「请重启盒子」，而是「正在重新启动蓝牙，也可以重启盒子。」；「复位了」「退出了」改为「已复位」「已退出」。其余：

| 原来 | 现在（标题／第二行） |
|---|---|
| 蓝牙未启动，正在重试，也可以重启盒子。 | 蓝牙未能启动／正在重试，也可以重启盒子。 |
| 有一部 iPhone 已不再与此盒子配对，请删除后重新添加。 | 有一部 iPhone 已不再与此盒子配对／请删除后重新添加。 |
| 证书 2026-11-20 到期。盒子未联网，无法续签，请插入可上网的 SIM 卡。 | 证书将于 2026-11-20 到期／盒子未联网，无法续签，请插入可上网的 SIM 卡。 |
| 证书已于 … 过期，车机会提示不安全。联网后会自动续签。 | 证书已于 … 过期／车机会提示不安全。联网后会自动续签。 |
| 缺少 CarPlay 认证文件，按「AI 安装说明」放置后将自动开始工作。 | 缺少 CarPlay 认证文件／按「AI 安装说明」放置后将自动开始工作。 |
| 盒子无 4G 网络：CarPlay 不受影响，车机自带的音乐、地图无法联网。 | 盒子无 4G 网络／CarPlay 不受影响，车机自带的音乐、地图无法联网。 |
| 盒子温度已达 74 °C，正在降速，CarPlay 可能卡顿。请移至阴凉处。 | 盒子温度已达 74 °C／正在降速，CarPlay 可能卡顿，请移至阴凉处。 |
| 特斯拉不支持 AutoPlay 热点当前的信道 52，请改为 149 或 36，国家选 CN。 | 特斯拉不支持信道 52／请将 AutoPlay 热点改为信道 149 或 36，国家代码选 CN。（带 OpenWrt 链接） |
| AutoPlay 热点使用 2.4 GHz：可以使用，但 5 GHz 更稳定，国内请用信道 149。 | AutoPlay 热点使用 2.4 GHz／5 GHz 更稳定，国内请改用信道 149。（能用，改为橙色） |
| 局域网地址是 …，不在 100.64.0.0/10 内，特斯拉浏览器无法访问。请在 … 改回 …，或重新安装 AutoPlay。 | 特斯拉无法访问局域网地址 …／它不在 100.64.0.0/10 内，请在 … 改回 …，或重新安装 AutoPlay。 |
| Tailscale 的防火墙会丢弃……的区域。请检查运营商/上游网络。 | Tailscale 的防火墙会拦截特斯拉／它丢弃……的区域。（原来末尾那句「请检查运营商/上游网络」对 Tailscale 不对，去掉） |
| usb0 已在用 …，与 … 冲突。请检查运营商/上游网络。 | usb0 与特斯拉的网段冲突／usb0 已在用 …，与 … 重叠，请检查运营商或上游网络。 |
| 暂时无法检查特斯拉网段冲突，请检查系统网络状态。 | 暂时无法检查特斯拉网段冲突／稍后会自动重试。 |

几条网络警告原来用「；」连成一条显示，现在各成一条。它们在 LuCI 里仍是一行，所以盒子写的仍是一句话，「：」前是标题、后是做法；盒子网页按第一个「：」（没有时按「，请」）拆开。

|---|---|

配对屏的两句结果仍在那一屏上（它每 3 秒刷新，提示框会反复弹出），改为同样的两行：「iPhone 未确认配对／请让 iPhone 停留在「设置 → 蓝牙」，再点一次它的名称。」「配对已取消或超时／请再点一次 iPhone 的名称。」恢复出厂设置成功后仍是顶部一条（绿色勾）：「已恢复出厂设置／盒子正在重新启动，之后请重新添加 iPhone。」

**提示框在没有脚本时也能用**：盒子网页是服务器画的，提示框是页面上的一层，「好」是回到这一页（不带这条消息）的链接；有脚本时「好」回到原来的分类，Esc 等于「好」，焦点在标题上（「好」上不画蓝框，和投屏页一样）。提示框在的时候页面不自动刷新（升级、配对时每 3 秒刷新会让它闪），点「好」后重新载入。顺带修了一处：带分类地址（如操作后回到 `#update`）打开页面时浏览器会跳过顶部的提示，现在新打开时停在顶部，刷新时保持原来的位置。

## 四、要在车上确认的

- CarPlay 主屏上「AutoPlay 设置」图标的名字是否完整显示。
- 浏览器检测的新样子在特斯拉浏览器里的字号（它在播放器脚本之前画，用自己的几条样式）。
- 配对完成或「接入 CarPlay」后，那部手机行里的「正在接入…」在 iPhone 连上时是否自己变成「正在使用」（每 3 秒刷新，最多 90 秒）。
- 选项菜单在特斯拉浏览器里是否从行下面弹出、点别处能关掉；「前往设置」是否打开到「视频编码」那一行。
- 新的系统颜色在白天的车机屏幕上看起来是否仍清楚（蓝色比原来浅一点）。
- 盒子网页的提示框在特斯拉浏览器里是否在页面中间、背景压暗，「好」能回到原来的分类。

**图标**（车主问：能否有更好的想法，要现代、高级，和 CarPlay 有一定联系）。原来的图标是 DashPlay 带来的「设置」符号（圆角框里两根滑杆）：名字改成「AutoPlay」后，图标代表的是这个产品；苹果的图标规范也不建议画界面控件、不建议用空心线框，提倡少量实心形状、渐变的底和层次。和 CarPlay 的联系只走合规的路：不用苹果的 CarPlay 标志或像它的图形（不用「播放」三角），而是同一套设计语言（圆角方形、白色或浅色主体、iOS 26 那种有光有层次的质感），以及它表达的事。草稿里否掉的：蓝底白「A」（像 App Store）、「Auto」字样（主屏上太小，和下面的名字重复，也容易被读成「自动」）。最后四个方向（图 `images/autoplay-icon-options-2026-11-14.png`）：
