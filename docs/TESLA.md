# 特斯拉专项

特斯拉是 AutoPlay 唯一的目标车机。这里只写事实和由事实推出的设置，来源是审计笔记 `browser_protocol_constraints.md` §2、《技术路径》§四、《特斯拉专属精简补充》和《dashplay-tesla 优化版分析》。标"未验证"的，是还没有在真车上确认过的。

## 1. 特斯拉浏览器的硬约束

| 约束 | 事实 | AutoPlay 的做法 |
|---|---|---|
| **拒绝私网地址** | 浏览器打不开 192.168/10/172.16 的地址，用域名也不行（2019 TMC、tesberry、DashPlay、WheelPlay 四处报告一致；有一份厂商页面说法相反）。100.64.0.0/10 的 CGNAT 地址能开 | 局域网固定 **100.96.0.1/24**，安装时写死（特斯拉专属补充 D1），不再运行时切换。保留"和 Tailscale/USB 随身 WiFi 冲突"的告警。特斯拉哪天把这段也拦了，这条路就断 |
| **Wi-Fi 必须有互联网** | 车不会停留在没有互联网的 Wi-Fi 上，不支持强制门户 | 插 SIM 让它真的上网；同时盒子**常驻应答**车机的联网检测（`answer_tesla_checks` 常量开，D4；7 个检测域名写死，固件更新可能加新的，要解析 `tesla-dns.log` 里未知的检测域名）。SIM 掉线时 10.25 起不再踢站，只在后台每 10 秒探测上游 |
| **挂挡就断 Wi-Fi** | 默认一出 P 挡（D 或 R）Wi-Fi 就关；2021.24 起每个网络可以单独打开"行驶中保持连接"（Remain Connected in Drive） | 必须在车上给盒子的 SSID 打开这个选项。页面侧计划：一趟里出现两次 3–10 秒、以 `online` 结束的断链，就常驻提示"请打开行驶中保持连接"（特斯拉专属补充 §四） |
| **5 GHz 信道** | 只认 36–48 和 149–165 | `channel=149`，国家码设成实际所在地（国内 CN；DashPlay 记录国内的车能看到 149、看不到 36）。`harden.sh` 第 2 项；运行时还缺一个"信道不在这两段就告警"的检查 |
| **行车时 `<video>` 受限** | "行车中视频播放受限，只有声音"；多个项目（Tesla Android、Carlinkit T2C、DashPlay）报告画到 canvas 的页面行车时照常 | 主链路 WebCodecs → canvas（A 档）。MSE 只能驻车用。**未验证**：这个判断只有项目报告，没有官方说明；2026.38 封掉后排屏变通做法说明特斯拉会管这类事 |
| **Chromium 版本不公开** | 2022 的 UA 数据是 Chromium 88；2026 项目在上面跑 WebCodecs，接收端日志见过 `chrome:148`；TslaMirror 说 MCU3 支持 H.265，MCU2（Intel Atom）2025.38.11 起支持 | 兼容显示模式按 `/Chrome\/(\d+)/` 自动判断（Chrome 113 要走兼容模式，120 以上正常），**跨 113 到 148 两头都不能写死**。UA 字符串本身没人见过，探测页第一行就是它 |
| **缩放** | 2026.26 起默认页面缩放提高且不可调；CSS 像素 ≠ 物理像素，DPR 约 1.53（**未验证**是否就是这次调高的结果） | 字号和触控目标按设备像素核对；探测页记录 `devicePixelRatio` 和 `visualViewport.scale` |
| **只有两种窗口形状** | 都是横屏、都带底栏：带边框约 773×601 CSS px，无边框约 1256×706 CSS px（对应 1922×1080 的流，底栏约 120px 仍在）。没有分屏、没有竖屏 | 分辨率策略可以大幅简化；长期可复活一个只有两种形状的视图区域，把带边框 ↔ 无边框的切换从 5–6 秒重连变成约 300ms（F3，不进第一个版本） |
| **麦克风和摄像头** | 2026.26 起按站点权限提示可用，**仅 Ryzen 车型**；摄像头只能驻车；麦克风行车时是否可用没说 | 特斯拉模式不向 iPhone 提供麦克风，通话和 Siri 走车的蓝牙，整条麦克风链路删除（D3） |
| **自动播放** | 浏览器音频要先点一下 | 页面在首次触摸前没有声音。导航播报（100/101 号流）由页面播放，所以"轻点任意位置开启声音"提示**必须保留且做大**（V7；dashplay-tesla 删掉它是回归） |
| **广告拦截** | 2026.32.3 加了网络请求级的拦截器，没有白名单界面 | **未验证**它是否影响局域网 WebSocket；探测页的可达性测试能看出 fetch 是否被拦 |
| **自动全屏** | 2026.26 起只对识别的流媒体域名自动全屏；`requestFullscreen` 过去不被接受 | 见第 3 节 |

## 2. 地址、证书与域名

- 车机打开的是 `https://<名字>.duckdns.org:18443/`。只有 DuckDNS + Let's Encrypt 这条路在特斯拉上验证过（DashPlay 2026-10-14）。"特斯拉浏览器无法跳过证书警告"**没有被验证**——那条记录写的是"某车机"；IP 直连加 JVM 自签名证书的兜底要留着（D7），探测页上记一下有没有"继续"按钮。
- 证书用 acme.sh 走 DNS-01，不开端口，靠 SIM 上网签发和续期（90 天）。所以**SIM 不是可选项**：没有网口、没有记录过任何无 SIM 的上网方式，不插 SIM 的盒子签不了也续不了证书（特斯拉专属补充 §六）。
- **未验证**：DuckDNS 和 Let's Encrypt 从国内 SIM 卡是否可达。dashplay-tesla 的作者说"DuckDNS 在国内访问不了"；如果对你的卡也成立，续期要改成"服务器端续期 + 盒子领取"（DECISIONS.md），这是上车前要先用这张卡试的事。
- 盒子的 dnsmasq 用 `address=/<名字>/100.96.0.1` 本地应答；OpenWrt 的 DNS 重绑定保护会丢上游返回的 100.64/10 地址，10.23 起把自己的名字放进了 `rebind_domain`。
- 名字固定：设了 DuckDNS 就用它，否则 `autoplay.lan`（D11）。

## 3. 无边框（全屏）

DashPlay 的做法是点按钮跳到腾讯视频 → 1905 → 再回到本页，利用特斯拉对流媒体域名的自动全屏去掉地址栏。代价：中间闪过第三方页面、页面重载、声音解锁丢失、CarPlay 重新挂接约 5 秒；没网时静默等 3 秒；跳转地址只有国内站点（海外要 `youtube.com/redirect`，2026.38 已封过一次 YouTube 的变通）。

AutoPlay 的决定（DECISIONS.md）：**保留跳转代码，默认关闭**。默认用带边框窗口（773×601 CSS px，1280×996 的流），dashplay-tesla 的作者三周实车就是这么用的；想要无边框的人在设置面板里手动点，面板里写清楚"全屏会经过视频网站跳转约 5 秒，期间无画面"，探测期间按钮禁用并显示"正在检查网络…"（V8）。无边框状态改按视口判断（`innerWidth × dpr ≥ 0.95 × screen.width × dpr`），不再靠 URL 里的标记。画面上不再放悬浮全屏按钮（V2）。

## 4. 声音：特斯拉蓝牙 + 页面播报

- iPhone 同时连特斯拉的蓝牙并**选为媒体来源**。音乐、通话、Siri、方向盘切歌、音量都是车的原生功能，不经过 F50。这是 DashPlay 特斯拉模式和商用 Carlinkit T2C 的做法，一举绕开回声、网页麦克风限制、自动播放、Wi-Fi 音频空洞四个坑（技术路径 §3.5）。
- **特斯拉页面不是无声的**：导航播报和提醒（100/101 号流）仍由页面播放并放大 3 倍；Siri 结束后 iPhone 还会往页面送约 27 秒的 102 号音乐流（所以 MSE 音乐路径只冻结不删，F1）。
- 页面播音乐时特斯拉的媒体卡片显示页面标题，保留 `document.title = '导航播报 · …'`（W3）。
- 计划加一条提示："音乐从页面出来了 → 把特斯拉设为媒体来源"（102 号流字节数超阈值时提示一次）。
- **未验证**：iOS 26 和 27 下导航播报到底从哪里出声（决定"轻点开启声音"提示的显示条件和 F1 的去留）。

## 5. 深浅色

iOS 27 用 `uiAppearanceUpdate` + `mapAppearanceUpdate`（`/info` 要声明 `enablesUIAppearance`/`enablesMapAppearance`），iOS 26 用 `setNightMode`；上游仍带着四个 DiPlay 的 `*AppearanceMode=0` 键把"自动"钉成了浅色（dashplay-tesla 分析 §三第 2 项）。特斯拉浏览器的 `prefers-color-scheme` 行为未知，探测页实时显示它。

## 6. 车上的设置清单

1. 车：Wi-Fi 连盒子的 SSID，打开"行驶中保持连接"。
2. 车：蓝牙连 iPhone，媒体来源选这部 iPhone。
3. 车：浏览器打开 `https://<名字>.duckdns.org:18443/`，加书签或设为主页（每次上车都要手动打开页面，WP8 的已知问题）。
4. 盒子：SIM 已插、`channel=149`、国家码正确（`harden.sh --status`）。
5. 页面：第一次触摸一下屏幕（开声音）。
6. 先停车跑一遍 `tools/probe/`，把结果存下来。

## 7. 特斯拉上还没有答案的

Model S/X 的视口、窗口放大后的尺寸、各代 MCU 的 Chromium 版本、`prefers-color-scheme`、明文 HTTP 能否打开 18080 设置页、重启后浏览器以哪种形状重开、方向盘按键是否交给网页、证书警告页有没有"继续"、广告拦截对局域网 WebSocket 的影响、行车时网页麦克风——都要一辆真车、一条日志。特斯拉相关的网页限制在 2026.26、2026.32、2026.38 都有改动，上车前再查一次更新说明。
