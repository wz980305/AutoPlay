# AutoPlay 1.2.0 界面迭代：车机窗口比例下的两张页面

日期：2026-11-02。承接 0.1.2（`docs/UI-0.1.2.txt`）的字号与触控尺度，这一轮回答两个问题：**车机浏览器不是标准比例时，`https://100.96.0.1:18443/` 的 CarPlay 页面和设置面板还好不好看、好不好点；`http://100.96.0.1:18080/` 的盒子设置页能不能按同一套逻辑优化。** 重点看下拉菜单和二级菜单。

## 一、测的是什么

| 形状 | CSS 像素 | 设备像素比 | 来源 |
|---|---|---|---|
| 特斯拉带边框窗口 | 773 × 601 | 1.53 | `docs/TESLA.md`（dashplay-tesla 作者三周实车的默认形态） |
| 特斯拉无边框页 | 1256 × 706 | 1.53 | 同上 |
| 更矮的窗口 | 1256 × 560 | 1.53 | 假设的最坏情况：键盘或更高的底栏 |
| 参考 | 1920 × 1200 | 1.0 | 1.2.0 之前在 Mac 上满意的形态 |
| 手机 | 390 × 844 | 3.0 | 只对盒子页：配对也会在手机上点 |

每个形状跑 Playwright 无头 Chromium，对投屏页截 17 张（等待、画面、三页设置、三个选择器打开、两个二级菜单展开、真实断线重连、英文、`carplay` 声音模式），对盒子页截 8 个状态 × 深浅色。全部可在台式机复现（§五），没有碰盒子、手机和车。

## 二、发现

**投屏页（18443）**

1. 0.1.2 的字号尺度在 773 × 601 下成立：根字号被 `clamp(20px, 2.78vmin, 24px)` 压到 20 px 下限，主标签 24 px、说明 20 px、行高 ≥ 72 px，没有横向溢出；三页设置的左侧导航占 12rem，右栏约 400 CSS px，中英文都放得下。
2. **五个原生 `<select>` 下拉（夜间模式、语言、CarPlay 内容大小、帧率、视频编码）是最大的问题**：下拉列表由浏览器自己画，字号是系统的、不随页面的 rem 变，行高十几像素、滚动条细，在 1.53 的屏上就是一小条；车机浏览器的弹出位置也不受页面控制。这是 0.1.2 没有覆盖的部分——当时只改了行本身。
3. 二级菜单（`<details>`：画质与兼容、连接与兼容性、备用控制）在 601 px 高的窗口里打开时往下展开，内容经常在折叠线以下，要再滚一次才看得到。
4. 声音走蓝牙（1.1.0 默认）时"常用"页顶上只剩一句说明，没有分组标题，孤零零的。
5. 断线重连、等待、浏览器检测页在三种形状下都完整可读；`#error-banner` 里的"详细信息"展开也在页内。

**盒子设置页（18080）**

6. 0.1.2 只改了投屏页；盒子页还是 17–19 px 的字、44 px 的行，和同一块屏上的投屏页设置不是一个尺度。
7. 配对过程中，配对码和「一致 / 不一致」按钮排在 Wi-Fi、链路图之后，在 773 × 601 下**在屏幕之外**，而且配对面板嵌在「iPhone」卡片里再套一层标题。
8. 「删除此 iPhone」和「立即升级」用浏览器的 `confirm()` 弹窗确认：车机浏览器要么按系统尺寸画一个小框，要么根本不弹（内嵌 Chromium 常见），后者意味着这两个操作在车上永远做不成。
9. 手机列表的二级菜单（点一部手机展开「接入 / 删除」）和投屏页一样会展开到折叠线以下。

## 三、改了什么

**投屏页**

- `src/picker.ts`（新）：选择行变成按钮，点开**页内选项表**——居中的 `<dialog>`，每个选项一行 ≥ 3.6rem（773 × 601 下 72 px），当前项打勾并获得焦点，下面一个「取消」；点背景或 Esc 关闭。原 `<select>` 留在 DOM 里隐藏，仍是值的持有者：`main.ts` 照旧读写 `.value`、监听 `change`，选项表选中时派发一次 `change`（选回当前项不派发）。`refreshPickers()` 在 `render()` 和显示设置读回后同步行上的当前值，语言切换时选项文字随之更新。
- 二级菜单：`<details>` 打开时若底边超出可视区，滚动把它整体带入（放得下时对齐底部，放不下时从标题开始）。
- 声音走蓝牙时，「常用」页显示「声音」分组和一张带蓝牙图标的卡片（标题「所有声音都走特斯拉蓝牙」，说明「含导航播报；音量在车上调，本页没有声音。」），取代原来的一句散文。
- `check-car.mjs` 新增选项表的检查（映射当前值、派发一次 change、关闭清空、禁用同步）。

**盒子设置页**

- `settings_ui.py` 的样式换到投屏页同一套令牌：根字号 `clamp(20px, 2.78vmin, 24px)`，`--hit: 3.2rem`，行标签 1.2rem、说明 1rem、分组标题 1rem、按钮 1.2rem；手机（≤ 480 px）回落到 17 px / 46 px。分隔线改 1 px（0.5 px 在 1.53 下会消失）。≥ 1100 px 宽时两栏。
- 配对进行中整页只有配对面板：确认阶段「配对码 → 两个按钮 → 一句说明」；等待阶段「附近的 iPhone 列表 → 取消 → 怎么做」。773 × 601 下配对码和按钮都在首屏。
- `confirm()` 全部去掉：「删除此 iPhone…」和「立即升级」第一次按下回到一个**确认屏**（`settings_page.confirm_screen`，`?ask=remove&phone=…` / `?ask=install`），写明后果，「取消」回首页，确认按钮带 `confirmed=1` 再提交。手机不在了或没有可装的版本时直接回到普通页。
- 页尾一段 6 行脚本：`<details>` 打开时按同样的规则滚入可视区；没有 JavaScript 时页面照常工作。

## 五、怎么复现

```sh
cd receiver/web && npm run build:offline                         # dist/
python3 ../../box/tools/render_settings_states.py out/box-states  # 盒子页 8 个状态的静态 HTML
CHROME=/path/to/chromium node scripts/ui-shots.mjs out/ui-shots   # 两张页面 × 所有形状；第二个参数 viewer|box 只跑一边
```

`ui-shots.mjs` 需要 `playwright-core`（或 `playwright`）和一个 Chromium；它自己起两个本地静态服务，mock 掉 `receiver-access.json`、`/api/display` 和 WebSocket（断线重连用真实的 socket 关闭 + 拒绝重连来触发），并把 H.264 探测强制为"支持"，无头 Chromium 没有硬件解码时才不会落到浏览器检测页。

## 六、没有验证、要在车上确认的

1. 特斯拉浏览器对 `<dialog>.showModal()` 嵌套（设置面板之上再开选项表）和 `height: fit-content` 的表现。两者都是 Chromium 很早就有的能力（37 / 46），而本页本来就要求 WebCodecs（94+），所以预期没有问题；万一选项表不出现，退路是把 `#picker` 的 `showModal` 换成 `open` 属性——代码里已经留了这一分支。
2. 原生 `<select>` 在车机上到底长什么样、`confirm()` 到底弹不弹，这一轮是按内嵌 Chromium 的常见行为推断的；1.2.0 不再依赖它们，所以答案不影响功能，但值得记到 `docs/TESLA.md` 的车机版本表里。
3. 773 × 601 下三页设置里仍要滚动的内容：常用页的定时说明和"本页语言与音量保存在此浏览器"、显示页的无边框和画质与兼容。这是信息量决定的，不是缺陷；真要省，可以把定时说明并入夜间模式行的副文字。
4. 浅色方案只对盒子页截了图（投屏页始终深色，`color-scheme: dark`）。

## 七、上车验收

停车后从驾驶座：打开设置 → 夜间模式，选项表一眼读清、拇指能点中任一项、「取消」能关；在显示页改一次「CarPlay 内容大小」再「应用并重连」，行上的值和重连后的画面一致；展开「画质与兼容」看它是否自己滚进视野。盒子页：点一部不在用的手机 → 「删除此 iPhone…」→ 确认屏出现、「取消」回到首页；添加 iPhone 时配对码与按钮不用滚动就能看到。日光和夜间各看一次。
