# AutoPlay 1.5.0 界面迭代：盒子网页与「AutoPlay 设置」同构

日期：2026-11-10。承接 1.3.0（`docs/UI-1.3.0.md`，投屏页的设置面板按 iOS「设置」收口）和 1.4.1（盒子设置页的横幅规则，`box/docs/STATUS-MODEL.md`）。这一轮只动盒子网页（`http://…:18080/`，从「AutoPlay 设置 → 连接 → 打开盒子网页」进来的那一页）和投屏页上通向它的链接。决定和没选的做法在 ADR-20。

## 一、车主的点与处理

| 车主的点 | 处理 |
|---|---|
| 重构这一页，提升美观度和信息呈现 | 整页换成面板的结构：标题栏、左侧分类、右侧一列分组（§二） |
| 设计美学和思路向「盒子设置」图标打开的「AutoPlay 设置」对齐 | 行高 3.6rem、图标 2rem、圆角 .75rem、字号、分组标题、尖角、颜色都取 `receiver/web/src/style.css` 的值；760 px 以下分类排成上方一行，也和面板一样 |
| 「每天自动检查一次，不会自动安装。」这样的小字可以移去 | 所有不随状态变化的说明都删了（§四）；分组下面的一行字只在有事发生时出现 |
| 考虑不同比例下的界面，「高级」左边有时空着 | 右侧永远只有一列。原来 1100 px 以上是两栏，右栏四个分组、左栏两个，窗口一宽「高级」左边就空出半屏 |
| 夜间模式通盘考虑，和手机上的状态一致 | 从投屏页进来时用 CarPlay 此刻的日间/夜间；手机直接打开时跟随手机（§三） |

## 二、页面现在的样子

- **标题栏**：「AutoPlay 盒子」（原来和面板同名，都叫「AutoPlay 设置」）。右侧一个按钮「CarPlay 画面」，回到投屏页——这台浏览器来时用的那个地址（域名或 IP；投屏页的设置按地址保存在浏览器里）。它对应面板的「完成」。滚动时标题栏留在顶部。
- **提示**：需要处理的状态和错误在标题栏下面，四个分类都看得到（规则不变，`box/docs/STATUS-MODEL.md`）。
- **iPhone**（进来时的分类）：连接链（Wi-Fi — 盒子 — iPhone，三个站点一条线，线到圆为止）；iPhone 列表和「添加 iPhone」。正在使用的那部是普通一行（绿色「正在使用」），其余的可展开出「接入 CarPlay」「删除此 iPhone…」。还没有 iPhone 时多一个分组，标题说明要到车机或另一台设备上添加，下面一行是本页地址。
- **网络**：交给 iPhone 的 Wi-Fi（名称；在 OpenWrt 后台设置）；在车机浏览器打开（投屏页的地址，来时用的排在前面）；自己的网址（网址、证书两行，证书有效时右侧是到期日，否则第二行写正在发生的事）。
- **更新**：本机程序 / 已是最新 / 有新版本（摘要最多四行 + 完整更新说明）/ 立即升级 / 检查更新。有新版本时左侧「更新」带红点，在任何分类都看得到。
- **高级**：盒子温度、下载诊断记录、恢复出厂设置。
- **只做一件事的屏**（添加 iPhone 的两步、删除和升级的确认、恢复出厂设置）：没有分类，一列居中，最宽 44rem；恢复出厂设置的标题栏按钮是「取消」。

分类用地址里的片段切换（`#net`、`#update`、`#more`），四页在同一份 HTML 里，CSS `:target` 决定显示哪一页，所以：检查更新时每 2 秒的自动刷新留在「更新」；按钮提交后盒子的重定向带上片段（`/update` → `#update`）；没有 JavaScript 也能用。页尾的小脚本只做两件事：切换分类不往浏览器历史里加记录（按浏览器的返回直接回投屏页），展开的行滚进可视范围。

## 三、日间/夜间

面板永远是深色。盒子网页带两套颜色：深色就是面板那一套（`#000` / `#1C1C1E` / `#0A84FF`…），浅色是 iOS 浅色下同样角色的值。

- **从投屏页进来**：两个「打开盒子网页」的链接带 `?night=1` 或 `?night=0`——投屏页按「夜间模式」（定时 18:30–06:30 / 跟随浏览器 / 日间 / 夜间）此刻向 iPhone 请求的结果，点的那一刻再算一次。盒子网页在画出任何东西之前读它，设 `data-theme`，记在这个标签页的 `sessionStorage` 里，再把查询串从地址中去掉。之后这次访问里的每一页——按钮提交后的重定向、自动刷新、恢复出厂设置——都是同一套颜色。
- **一小时没有新的结果**，或**从来没有**（手机直接打开、书签）：跟随浏览器自己的深色/浅色。
- 所以 iPhone 上 CarPlay 是夜间时，车机上的盒子网页是深色；是日间时是浅色。手机上直接打开，跟随手机。

## 四、去掉的字

「每天自动检查一次，不会自动安装。」「车机连上「…」后，在浏览器打开上面的地址。」（改成分组标题「在车机浏览器打开」）「添加 iPhone 时，请在车机或另一台设备上操作。」「配对一次后，iPhone 连上这个 Wi-Fi 就会自动接入。」「正在使用。它断开后，才能接入别的 iPhone 或删除它。」、每部 iPhone 名字下的「蓝牙 …xx:xx」（两部同名时仍显示，删除确认屏上也保留）、「在 OpenWrt 后台设置 Wi-Fi」里重复的「Wi-Fi」、有新版本那一行里的「当前 x.y.z」（上面一行就是本机程序）、附近 iPhone 列表右侧的「配对」。

留下的：正在发生的事（已邀请 1 分钟内有效、升级被拒的原因、正在升级约 2–5 分钟、蓝牙就绪后才能添加）；添加 iPhone 的三步和核对配对码的那一句；删除、升级、恢复出厂设置的确认屏上说明后果的话。

## 五、怎么复现

```sh
cd receiver/web && npm run build:offline && npm test
python3 ../../box/tools/render_settings_states.py out/box-states          # 13 个状态
CHROME=/path/to/chromium node scripts/ui-shots.mjs out/ui-1.5.0 box       # 5 形状 × 16 张，窗口和手机两种形状各拍夜间、日间
cd ../../box && python3 -m unittest discover -s tests/onecloud             # 268
```

`ui-shots.mjs` 按投屏页的方式打开每一张（`?night=1|0`），并把浏览器自己的偏好设成相反的，颜色取错了一眼可见；它同时核对有无横向溢出、查询串是否已从地址中去掉。台架上量到的：773 × 601 下标题 32 px、行标签 24 px、行高 72 px、分类 220 × 72 px，与面板相同。另用真实的页面服务（假状态）在浏览器里点过一遍：切换分类不增加历史记录、切换后回到页顶、检查更新期间自动刷新留在「更新」、邀请的结果出现在 iPhone 分组下、进出恢复出厂设置颜色不变。

## 六、要在车上确认的

1. 夜间模式为夜间时从「打开盒子网页」进来是深色，日间时是浅色；在页面里点几次按钮后颜色不变。
2. 白天从深色的面板进到浅色的盒子网页，是否觉得突兀（ADR-20 末尾：可以改成从车机进来时永远深色）。
3. 点左侧分类是否立即切换；滚动时标题栏和分类是否稳稳留在原处。
4. 「CarPlay 画面」是否回到投屏页并恢复画面；浏览器的返回键是否一次就回到投屏页。
5. 773 × 601 的窗口里，「iPhone」分类不滚动就能看到连接链、两部 iPhone 和「添加 iPhone」。
