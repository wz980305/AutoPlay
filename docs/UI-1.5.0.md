# AutoPlay 1.5.0 界面迭代：盒子网页与「AutoPlay 设置」同构，两者随日间/夜间换色

日期：2026-11-10。承接 1.3.0（`docs/UI-1.3.0.md`，投屏页的设置面板按 iOS「设置」收口）和 1.4.1（盒子设置页的横幅规则，`box/docs/STATUS-MODEL.md`）。这一轮重排盒子网页（`http://…:18080/`，从「AutoPlay 设置 → 连接 → 打开盒子网页」进来的那一页），给设置面板加上日间的一套颜色，并理顺两者之间的来回。决定和没选的做法在 ADR-20。

## 一、车主的点与处理

| 车主的点 | 处理 |
|---|---|
| 重构这一页，提升美观度和信息呈现 | 整页换成面板的结构：标题栏、左侧分类、右侧一列分组（§二） |
| 设计美学和思路向「盒子设置」图标打开的「AutoPlay 设置」对齐 | 行高 3.6rem、图标 2rem、圆角 .75rem、字号、分组标题、尖角、颜色都取 `receiver/web/src/style.css` 的值；760 px 以下分类排成上方一行，也和面板一样 |
| 「每天自动检查一次，不会自动安装。」这样的小字可以移去 | 所有不随状态变化的说明都删了（§四）；分组下面的一行字只在有事发生时出现 |
| 考虑不同比例下的界面，「高级」左边有时空着 | 右侧永远只有一列。原来 1100 px 以上是两栏，右栏四个分组、左栏两个，窗口一宽「高级」左边就空出半屏 |
| 夜间模式通盘考虑，和手机上的状态一致 | 从投屏页进来时用 CarPlay 此刻的日间/夜间；手机直接打开时跟随手机（§三） |
| 「AutoPlay 设置」页面也更新 | 面板和它的选项弹层有了日间的一套颜色，和盒子网页的逐项相同，按「夜间模式」的结果切换（§三） |
| 等待画面也跟随 | 等待画面同样换色；页面头部先按同一规则定好日夜，打开时不闪（§三） |
| 「请先打开盒子网页」的提示让人去点一个不存在的按钮（审查时发现，车主同意改） | 标题改为「未取得盒子的访问许可」，说明改为检查盒子电源与热点、刷新本页 |
| 等待画面上「配对 iPhone，查看热点与证书。」「使用浏览器返回按钮退出。」能否也去掉 | 去掉了。等待画面的三行现在和面板的行一样，只有图标、名称、尖角；同一行在其他状态下的两句也一并去掉（§四） |
| 盒子网页的「CarPlay 画面」是否改为退回「AutoPlay 设置」，「完成」照旧回 CarPlay | 是。按钮改为「返回」，回到进来的地方：从面板进来回面板的「连接」，从等待画面进来回等待画面（§二） |

## 二、页面现在的样子

- **标题栏**：「AutoPlay 盒子」（原来和面板同名，都叫「AutoPlay 设置」）。右侧一个按钮，是这一页的出口，对应面板的「完成」。滚动时标题栏留在顶部。按钮按来路分三种：
  - 从面板（连接 → 打开盒子网页）进来：「返回」，回到投屏页并打开面板的「连接」；在那里点「完成」回到 CarPlay。进来是两步，出去也是两步。
  - 从等待画面的「打开盒子网页」进来：「返回」，回到等待画面。
  - 手机直接打开、书签：没有可退回的地方，按钮是「CarPlay 画面」，去投屏页。
  去的都是这台浏览器来时用的那个地址（域名或 IP；投屏页的设置按地址保存在浏览器里）。
- **提示**：需要处理的状态和错误在标题栏下面，四个分类都看得到（规则不变，`box/docs/STATUS-MODEL.md`）。
- **iPhone**（进来时的分类）：连接链（Wi-Fi — 盒子 — iPhone，三个站点一条线，线到圆为止）；iPhone 列表和「添加 iPhone」。正在使用的那部是普通一行（绿色「正在使用」），其余的可展开出「接入 CarPlay」「删除此 iPhone…」。还没有 iPhone 时多一个分组，标题说明要到车机或另一台设备上添加，下面一行是本页地址。
- **网络**：交给 iPhone 的 Wi-Fi（名称；在 OpenWrt 后台设置）；在车机浏览器打开（投屏页的地址，来时用的排在前面）；自己的网址（网址、证书两行，证书有效时右侧是到期日，否则第二行写正在发生的事）。
- **更新**：本机程序 / 已是最新 / 有新版本（摘要最多四行 + 完整更新说明）/ 立即升级 / 检查更新。有新版本时左侧「更新」带红点，在任何分类都看得到。
- **高级**：盒子温度、下载诊断记录、恢复出厂设置。
- **只做一件事的屏**（添加 iPhone 的两步、删除和升级的确认、恢复出厂设置）：没有分类，一列居中，最宽 44rem；恢复出厂设置的标题栏按钮是「取消」。

分类用地址里的片段切换（`#net`、`#update`、`#more`），四页在同一份 HTML 里，CSS `:target` 决定显示哪一页，所以：检查更新时每 2 秒的自动刷新留在「更新」；按钮提交后盒子的重定向带上片段（`/update` → `#update`）；没有 JavaScript 也能用。页尾的小脚本只做两件事：切换分类不往浏览器历史里加记录（按浏览器的返回直接回投屏页），展开的行滚进可视范围。

## 三、日间/夜间

投屏页自己的界面原来永远是深色。现在它和盒子网页有同样的两套颜色：深色是面板原来那一套（`#000` / `#1C1C1E` / `#0A84FF`…），浅色是 iOS 浅色下同样角色的值（`#F2F2F7` / `#FFF` / `#007AFF`…）。两份样式表（`receiver/web/src/style.css`、`box/scripts/onecloud/settings_ui.py`）各写各的，`test_the_panel_and_this_page_share_their_colours` 逐项核对。

- **用哪一套由「夜间模式」决定**（定时 18:30–06:30 / 跟随系统 / 始终白天 / 始终夜间）：投屏页本来就按它算出日间或夜间发给 iPhone，现在同一个结果也设在页面上（`data-theme`），等待画面、面板和选项弹层随之换色；在弹层里改了立即生效，定时的分界过了之后 30 秒内切换。
- **等待画面不闪**：它写在 `index.html` 里，在脚本包运行之前就画出来。所以页面头部有几行内联脚本，按和 `night.ts` 的 `isNight()` 相同的规则先设好 `data-theme`；`check-car.mjs` 把这几行取出来，对每种模式、分界前后的时刻、浏览器的深浅偏好逐一和 `isNight()` 对照（84 种），两处不会各走各的。
- **属于画面的部分不换色**：四周的黑边、重连时的遮罩、画面上的轻提示和错误条、调试浮层仍是深色。面板里出现的轻提示也保持深色胶囊。
- **盒子网页**：两个「打开盒子网页」的链接带 `?night=1|0`（同一个结果，点的那一刻再算一次）和 `from=panel|page`（从哪里点的）。盒子网页在画出任何东西之前读它们，设 `data-theme` 和 `data-from`，记在这个标签页的 `sessionStorage` 里，再把它们从地址中去掉。之后这次访问里的每一页——按钮提交后的重定向、自动刷新、恢复出厂设置——都是同一套颜色、同一个「返回」。
- **一小时没有新的结果**，或**从来没有**（手机直接打开、书签）：盒子网页跟随浏览器自己的深色/浅色。
- 所以 iPhone 上 CarPlay 是夜间时，面板和车机上的盒子网页都是深色；是日间时都是浅色。手机上直接打开盒子网页，跟随手机。
- 日间的面板里，行与行之间的线是 1 px（深色是 .5 px）：半像素的线在浅色页面、特斯拉 1.53 的缩放下会消失，盒子网页 1.2.0 时遇到过。

**返回的实现**：盒子网页的按钮在 `data-from=panel` 时指向 `https://…:18443/#settings=connection`。投屏页启动时见到 `#settings=<分类>` 就选中那个分类、打开面板，并立刻把片段从地址里去掉（刷新页面显示的是画面，不会再弹出面板）。

## 四、去掉的字

「每天自动检查一次，不会自动安装。」「车机连上「…」后，在浏览器打开上面的地址。」（改成分组标题「在车机浏览器打开」）「添加 iPhone 时，请在车机或另一台设备上操作。」「配对一次后，iPhone 连上这个 Wi-Fi 就会自动接入。」「正在使用。它断开后，才能接入别的 iPhone 或删除它。」、每部 iPhone 名字下的「蓝牙 …xx:xx」（两部同名时仍显示，删除确认屏上也保留）、「在 OpenWrt 后台设置 Wi-Fi」里重复的「Wi-Fi」、有新版本那一行里的「当前 x.y.z」（上面一行就是本机程序）、附近 iPhone 列表右侧的「配对」。

投屏页的等待画面（1.3.0 时作为首次使用的引导保留了下来）：「打开盒子网页」下的「配对 iPhone，查看热点与证书。」；「无边框模式」一行在三种状态下的第二行——「使用浏览器返回按钮退出。」（已开启）、「经视频网站跳转，约 5 秒后返回并隐藏地址栏。期间画面会中断。」（未开启）、「跳转需要车机能够访问互联网。」（检查网络时）。车主点名的是第一句和「使用浏览器返回按钮退出。」；后两句在同一行的另外两种状态下出现，留着的话退出无边框后又会看到小字，所以一起删。状态标题下面那一句（如「打开 iPhone 的蓝牙与 Wi-Fi，已配对设备会自动连接。首次使用，请先在盒子网页配对。」）说的是此刻的状态，保留。字串 `boxLinkHint`、`borderlessOnHint`、`fullscreenRowHint`、`checkingNetworkHint` 删除。

留下的：正在发生的事（已邀请 1 分钟内有效、升级被拒的原因、正在升级约 2–5 分钟、蓝牙就绪后才能添加）；添加 iPhone 的三步和核对配对码的那一句；删除、升级、恢复出厂设置的确认屏上说明后果的话。

## 五、怎么复现

```sh
cd receiver/web && npm run build:offline && npm test
python3 ../../box/tools/render_settings_states.py out/box-states          # 13 个状态
CHROME=/path/to/chromium node scripts/ui-shots.mjs out/ui-1.5.0 box       # 5 形状 × 16 张，窗口和手机两种形状各拍夜间、日间
cd ../../box && python3 -m unittest discover -s tests/onecloud             # 268
```

`ui-shots.mjs` 按面板链接的方式打开盒子网页的每一张（`?night=1|0&from=panel`），并把浏览器自己的偏好设成相反的，颜色取错了一眼可见；它同时核对有无横向溢出、查询串是否已从地址中去掉。投屏页那一半固定在「始终夜间」拍原来的一套，另在窗口和无边框两种形状下以「始终白天」拍等待画面、面板、弹层和面板里的提示，最后在弹层里选「始终夜间」确认当场变深。台架上量到的：773 × 601 下标题 32 px、行标签 24 px、行高 72 px、分类 220 × 72 px，与面板相同。另用真实的页面服务（假状态）在浏览器里点过一遍：切换分类不增加历史记录、切换后回到页顶、检查更新期间自动刷新留在「更新」、邀请的结果出现在 iPhone 分组下、进出恢复出厂设置颜色不变。整个来回也走过：面板「连接」→ 打开盒子网页（按钮是「返回」，按过别的按钮后仍是）→ 返回（面板开在「连接」，地址里没有片段）→ 完成 → 刷新（没有面板）；从等待画面进来再返回（没有面板）；夜间一遍；不带参数直接打开（按钮是「CarPlay 画面」）。

## 六、要在车上确认的

1. 日间时等待画面、「AutoPlay 设置」和盒子网页都是浅色，夜间时都是深色；在「夜间模式」里改一下，当场跟着变。白天打开投屏页时不应先黑一下再变白。
2. 从 CarPlay 点「盒子设置」→ 连接 → 打开盒子网页 → 返回：是否回到「AutoPlay 设置」的「连接」；再点「完成」是否回到 CarPlay 画面。
3. 盒子网页里点左侧分类是否立即切换；滚动时标题栏和分类是否稳稳留在原处。
4. 日间的面板里行与行之间的线是否看得见、是否嫌粗。
5. 白天浅色的等待画面换成 CarPlay 画面的那一下是否自然（画面四周的黑边仍是黑的）。
6. 773 × 601 的窗口里，盒子网页的「iPhone」分类不滚动就能看到连接链、两部 iPhone 和「添加 iPhone」。
