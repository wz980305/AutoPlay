# 决策记录

每条一段：背景 → 决定 → 代价。编号不复用；推翻一条时在它下面加"已被 ADR-n 取代"，不删。来源缩写：技术路径 = 《F50 车机浏览器 CarPlay 技术路径》；硬件 = 《硬件视角审查与精简方案》；路线图 = 《日常使用加固路线图》；界面 = 《界面审查》；特斯拉补充 = 《特斯拉专属精简补充》；变更评估 = 《DashPlay 2026.10.25 变更评估》；dashplay-tesla = 《dashplay-tesla 优化版分析》。

## ADR-1 硬分叉，不再维护补丁

DashPlay 以 63 个无上下文（`--unidiff-zero`）的补丁叠在 PlayPort `9a0882d` 上，1.7 万行，存在补丁改补丁的链条，三天里对 `display-fit.ts`/`main.ts` 叠了 7 个互相覆盖的补丁；PlayPort 上游只有 5 个提交，已停更，没有跟踪价值（硬件 §2.2 第 1 项、变更评估 §四）。**决定：** 把 PlayPort 导入为 git 基线，按补丁顺序逐个提交，之后所有改动都是普通提交；界面优化从这一步之后开始。**代价：** 以后从 DashPlay 吸收改动要靠 cherry-pick 或手工移植，而 DashPlay 每 2–3 天一版；需要每周对照一次直到分叉稳定。

## ADR-2 只做 F50 + 特斯拉

上游支持 Debian/Armbian、N1、玩客云、有线、macOS、手机上网、外接路由、公网 IPv6，F50 实际执行的代码约 2.1 万行，仓库却带着约 1.2 万行 F50 永远用不到的代码；再收窄到特斯拉还能砍约 3200 行，uci 从 22 键减到 7 键（硬件 §一、特斯拉补充 §一）。**决定：** 目标只有一个硬件（F50，B16 固件，mu300-linux 5.4）和一个车机（特斯拉浏览器）；局域网 100.96.0.1/24 安装时写死；麦克风链路、媒体会话、小鹏全屏家族、Debian/N1/有线路径删除。**代价：** 别的车（小鹏可行、其他待探测）和别的盒子不再是这个仓库的范围；首次安装会像今天的特斯拉阶段一样断一次 SSH；卸载不恢复旧地址。

## ADR-3 性能模式默认关，分辨率按温度门限

上游 10.23 新增的"性能模式"默认开：每个窗口放大到最清晰尺寸（长边 1280 到 1920，快解码器到 2560）再缩回显示，上游自己注明"解码更重"；而 F50 的热预算约 3W，推算的投屏功耗就是 1.7–2.9W，40°C 车内几分钟就降频，2560px 让每帧工作量增加 50–100%（硬件 H1；变更评估 §四第 3 条）。**决定：** 性能模式默认关；自动分辨率的上限按 `soc-thmzone` 温度回退（≥80°C 从 2560 降到 1920/1280、30fps 降到 24fps）；特斯拉默认界面尺寸 300mm 档。**代价：** 画面比上游默认模糊一些；温度门限需要测量数据来定，目前是推算。

## ADR-4 保留并放大"轻点开启声音"提示

特斯拉模式不是无声的：导航播报和提醒（100/101 号流）由页面播放并放大 3 倍，Siri 结束后 iPhone 还会送约 27 秒的 102 号音乐流；Chromium 的自动播放策略要求先有一次触摸（特斯拉补充 §一第 1 条；界面 V7）。dashplay-tesla 分支删掉了这个提示，在它自己的"声音=CarPlay"模式和所有无人点屏的自动连接会话里都是回归。**决定：** 保留提示，改成贴底边的整宽半透明条或居中 ≥28px 的胶囊，出现时脉冲一次，自动重载后立刻重新显示；条件显示（AudioContext 挂起且确实收到了要播的流时）。**代价：** 多一个常驻状态；在"播报其实从车机蓝牙出来"的 iOS 版本上可能多余——这要一辆车来确认。

## ADR-5 冻结不删：MSE 音乐路径与视图区域

MSE 音乐路径（`music-output.ts`、`aac-mp4.ts`，约 250 行）：网页端笔记认为可删（`AudioDecoder` 走 Web Audio 能接住），盒子侧笔记认为删了有"Siri 后静音"的风险，替代方案 `disableAudioOutput` 未测过（特斯拉补充 F1）。视图区域（约 380 行 + 1144 行补丁）：10-23 起页面不再调用，但一个只有两种横屏形状的极简版能把带边框 ↔ 无边框切换从 5–6 秒重连变成约 300ms（F3）。**决定：** 两者都放在编译开关/冻结状态，不再开发也不删，等一趟实车确认后再决定。**代价：** 仓库里多留约 630 行暂时无用的代码。

## ADR-6 JVM 先用，Rust 在后

JVM 不是 CPU 瓶颈（每帧 0.35–0.7ms on A76），但形态不对：8 次拷贝、约 190KB 垃圾/帧、JIT 高峰落在每次开机最热的一分钟、Serial GC 停顿落在帧周期里；换原生只省整机 20–40% 的 CPU，因为内核和驱动才是大头；原生的收益在确定性、内存和启动。GraalVM 不可行（aarch64 musl 没有静态 JDK 库），从 UxPlay 改不划算（没有 CarPlay 部分）（硬件 H4、§四）。**决定：** 路线 B 先行——一个静态链接的原生守护进程 `autoplayd` 替掉全部 Python，JVM 保留为协议引擎；再以三个去风险原型（Unix socket 喂原生 WSS 转发器、LIVI crate 用稳定版 Rust 编成 aarch64-musl、iAP2 引导对等比对）为门槛做路线 C（`engine=jvm|native`，复用 LIVI 的 GPL-3.0-or-later crate）。**代价：** 两个阶段加起来 16–24 人周；LIVI 单作者、钉在 Rust beta 频道、与其 HelperSock 耦合，拿出来是移植不是引用；协议对等（视图区域、UI 缩放、102 号流只接受 AAC 等车机调校）要逐项重验。

## ADR-7 证书续期保留"服务器端续期 + 盒子领取"选项

只有 DuckDNS + Let's Encrypt 在特斯拉上验证过；续期靠 SIM 上网、在盒子上跑 acme.sh；DuckDNS 的续期只在启动时和每小时一次尝试，一小时以内的通勤永远续不上（路线图 WP3）。dashplay-tesla 的作者说"DuckDNS 在国内访问不了"，并实现了服务器端续期 + 证书包校验 + 盒子领取（dashplay-tesla §三第 7 项）。**决定：** 先把盒子上的续期做对（WAN 连上/NTP 同步时触发、60 秒起退避、到期日显示在页面上）；同时把"服务器续期、盒子通过 HTTPS 领取签名过的证书包"做成可选路径，**不**采用反向 SSH 直通 root 的维护通道。**代价：** 需要用户自己有一台能上网的服务器；上车前要先用这张 SIM 卡实测 `duckdns.org` 和 Let's Encrypt 的可达性来决定走哪条。

## ADR-8 无边框跳转保留代码、默认关闭

DashPlay 靠跳到腾讯视频 → 1905 → 回本页来拿无边框，中间闪过第三方页面、重载、声音解锁丢失、CarPlay 重挂约 5 秒；跳转地址只有国内站点；2026.38 已封过一次 YouTube 的变通，说明这招随时可能失效（界面 V8；dashplay-tesla §四"删掉特斯拉全屏跳转"）。dashplay-tesla 作者只用带边框窗口（773×601 CSS px）三周实车。**决定：** 默认带边框；跳转代码保留，在设置面板里手动触发，面板写明代价；画面上不再放悬浮全屏按钮。**代价：** 默认画面比无边框小（1280×996 的流对 1922×1080），CarPlay 界面密度按毫米档另配。

## ADR-9 画面主链路 WebCodecs → canvas，音频走车载蓝牙

特斯拉行车时禁 `<video>` 只留声音，画到 canvas 的页面多个项目报告行车可用；WebCodecs 延迟最低、F50 只转发不转码（技术路径 §一第 5、6 条）。车载蓝牙模式一举绕开回声、网页麦克风限制、自动播放、Wi-Fi 音频空洞四个坑。**决定：** A 档（WebCodecs）默认；MSE 为驻车兼容档；WebRTC/C′ 待探测页结果再定；音乐、通话、Siri 走特斯拉蓝牙，页面只管画面和播报。**代价：** 必须 HTTPS（证书方案不可省，除非 C′ 成立）；声音可能比画面略慢（蓝牙延迟，推断）。

## ADR-10 先搭测量体系再动手优化

F50 上没有任何实测数据：功耗、温度、CPU、GC 停顿、延迟全是推算（硬件 §七、路线图 §一）。**决定：** `tools/f50/measure.sh` 和 `tools/car/touch-latency.md` 先于一切性能改动；每项优化必须有前后对比的 `measure-report.py` 输出和相机法 P50/P95；没有基线的优化不合并。**代价：** 第 1 周几乎没有"功能"产出。

## ADR-11 刷机、root、回安卓只引用 mu300-linux 的文档

mu300-linux 单维护者、33 天约 25 个版本、每个版本都可能改安装流程；DashPlay 靠精确文本匹配去改 mu300 的脚本，升级就被还原（PA#6、PA#17）。**决定：** 本仓库不写任何刷机或 root 步骤，只链接到 mu300-linux 的 wiki；`harden.sh` 对 mu300 文件的唯一修改（`extra-modules`）保留备份、可回退、幂等，并在文档里写明升级后要重跑。**代价：** 用户要跨两个项目的文档；mu300 改了命令名时 `harden.sh` 会退化成打印指引。

## ADR-12 自有域名的第二个签发源：腾讯云 DNSPod（1.0.0 加入，1.0.1 记录）

DuckDNS 从国内 SIM 的可达性一直是未验证项，dashplay-tesla 的作者说它访问不了；1.0.0 在实车前加了 DNSPod 路线（`dns_provider=dnspod`，acme.sh 的 `dns_dp` 钩子，Let's Encrypt DNS-01），并在车里拿到了证书。**决定：** 两条路线并存，uci `dns_provider` 切换，默认 DuckDNS；DNSPod 路线由盒子本地 dnsmasq 应答域名，但**推荐**车主在控制台另加一条指向 100.96.0.1 的 A 记录，让公网解析也成立（DuckDNS 路线天然如此）。不采用 ADR-7 的"服务器端续期 + 盒子领取"，因为盒子直接签发已经证明可行。**代价：** DNSPod 的 API Token 是账号级凭证，能改账号下所有域名的解析；它存在 `/etc/config/autoplay`（0600）和 `state/acme/account.conf`，出厂重置会清掉。更稳的方案是改用 acme.sh 的 `dns_tencent` 钩子配腾讯云 CAM 子账号的 `SecretId/SecretKey`（可以把权限收窄到单个域名），列入待办。

## ADR-13 5 GHz 固定 CN / 149–165，安装时写入，不做 uci 选项（1.0.0 加入，1.0.1 修正）

实车（2026-11-02）：车机只在 149–165 上搜得到热点，而 mu300 厂商镜像的国家码 TR 没有 149–165 且把 `channels` 锁在 36–48。**决定：** 安装包的 uci-defaults 把每个 5 GHz 射频设为 CN，信道不在 149–165 时设为 149，删除 `channels` 锁；车主在 LuCI「网络 → 无线」里改到 153–165 的选择在升级时保留（1.0.1）。不另加 `autoplay.main.wifi_*` 选项：无线配置已经有 LuCI 自己的页面，再加一层只会两处打架。**代价：** 不在中国使用的车主，国家码仍会被写成 CN；149–165 在多数地区是合法频段，但法规上应填实际所在地——需要时在 LuCI 里改国家码，升级不会动它（脚本只在国家码不是 CN 时才写 CN，所以改成别的会被改回；这一点是已知限制，若有海外用户再做成选项）。

## ADR-14 声音默认全部走特斯拉蓝牙；网页永远不播音乐（1.1.0）

1.0.x 沿用 DashPlay 特斯拉模式的分路：音乐、Siri、通话走车机蓝牙，导航播报由网页播放（需要轻点解锁、独立音量、Web Audio 一整套代码）。上游 2026-10-31～11-01 的实测给出两件事：(1) 完全不声明音频格式时 iPhone 不建立任何音频流，所有声音按它不在 CarPlay 时的规则走已连接的蓝牙设备，上游把它做成了特斯拉用户的"导航也走特斯拉蓝牙"选项；(2) 行驶中的特斯拉对正在播音乐的网页弹"视频只有声音"横幅，横幅改变页面尺寸，CarPlay 每约 10 秒重协商一次。**决定（项目组 2026-11-02）：** 默认 `audio_route_navigation=bluetooth`——接收端 `disableAudioOutput`，页面无声且不打开音频输出；`carplay` 作为备选保留（页面播导航），经蓝牙听不到播报时切回。无论哪种模式，页面都不再播放音乐：`media` 类型的流直接丢弃并提示一次，MSE 音乐路径删除（ADR-5 的冻结项结束）。**代价：** `bluetooth` 模式在行驶中还没有验证（上游注释只记录了"无音频流"，没有记录听到播报）；A2DP 起播可能吃掉播报的第一个字；iPhone 没连车机蓝牙时声音会从手机出来。**收益：** 少一步"轻点开启声音"、一处音量、去掉 Web Audio 的全部失效模式，网页音频代码只剩 `carplay` 备选所需的部分。

## ADR-15 车机上不依赖浏览器自带的弹出界面：下拉、确认框都在页内画（1.2.0）

车机浏览器自己画的东西——`<select>` 的下拉列表、`confirm()` 对话框——字号是系统的、不随页面的 rem 变，位置不受页面控制，内嵌 Chromium 还可能根本不弹 `confirm()`。0.1.2 把两张页面的行和按钮做到了 24 px / 64 px 的尺度，但这些弹出层还是十几像素的一小条（`docs/UI-1.2.0.md` §二）。**决定：** 投屏页的五个选择用页内选项表（`picker.ts`，`<dialog>`，每项一行 ≥ 3.6rem），原 `<select>` 隐藏着保留为值的持有者，这样 `main.ts` 的读写与 `change` 监听一个字不改；盒子页的「删除此 iPhone」「立即升级」改为服务器渲染的确认屏（`?ask=…` + `confirmed=1`），不用 JavaScript 也成立；两张页的 `<details>` 二级菜单打开时自己滚入可视区。盒子页的样式令牌和投屏页统一。**代价：** 多一个 `<dialog>` 和 90 行脚本；确认多一次整页往返（盒子页本来就是整页刷新的）；特斯拉浏览器对嵌套 `showModal()` 的表现待实车确认，代码里留了 `open` 属性的退路。**不做的：** 不自绘滚动条、不自绘开关（原生 checkbox 已用 CSS 画成开关）、不动 LuCI 页面（那是 OpenWrt 的界面，在车上不用）。
